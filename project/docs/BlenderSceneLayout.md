# Blenderでシーン配置を配置する

Blenderのメッシュを配置し、OBJ・基本テクスチャ・配置JSONを一括で書き出せます。
TKMAXではシーン配置を一度読み込むだけで全モデルを生成します。オブジェクトごとの
生成コードやCatalogへの登録は不要です。

## 最初の確認

GAMEシーンのImGui「Blenderシーン配置」で「サンプルを読込」を押すと、床と壁の配置を確認できます。
通常起動で読む `resources/layouts/layout.json` は空なので、既存のゲーム配置は変更しません。

## Blenderの準備（4.x向け）

1. リポジトリ内の `tools/blender/tkmax_scene_layout_export.py` をBlenderへインストールします。
   PreferencesのAdd-onsにあるInstall（4.2以降はメニューのInstall from Disk）でこの.pyを選び、有効にします。
   Blenderのバージョンによっては旧形式のアドオン（Legacy Add-on）として表示されます。
2. Blenderで床・壁などのメッシュを配置します。複製して並べたものもまとめて書き出せます。
3. File → Export → TKMAX Scene Layout (.json) を選びます。Scene Properties内のTKMAX Scene Layoutからも開けます。
4. **TKMAXリポジトリの `project/resources/layouts/layout.json`** を書き出し先に選びます。
   別シーン配置を作る場合は、同じlayoutsフォルダへ別名.jsonで保存してください。
5. ゲームの「Blenderシーン配置」で「読込 / 再読込」を押します。
   別名の場合は「配置JSON」を `resources/layouts/別名.json` に変更して読み込みます。

配置変更のたびにGameSceneを書き換える必要はありません。
JSONは一時ファイルから置き換えるため、途中で失敗した書き出しで前の配置JSONは壊しません。
.blend自体も保存しておいてください。ゲームから.blendを直接読んだり、リアルタイム通信したりする方式ではありません。

## 自動で書き出す内容

- 現在のビューレイヤーで表示され、レンダー無効になっていないメッシュ。
- モディファイア適用後の静的な形状、三角形、UV、コーナー法線。
- 基本のBase Color画像、または単色のマテリアル色。画像はPNGでコピーします。
- オブジェクト名、位置、回転（ラジアン）、拡大縮小。
- Emptyは名前・tag・Transformを持つマーカーとして保存します。

親子付けはワールド配置にまとめて出力します。BlenderのZ上向きとTKMAXのY上向き、
左右の座標系、現行OBJローダーの法線・面順序・UV規約を変換します。
通常は手動で座標やモデルを回転して合わせる必要はありません。
同一の形状・マテリアルは同じ資産を共有します。

生成先は `resources/obj/blender_layout_assets/` と、その中のtexturesフォルダです。
ファイル名は内容から決めるため、モデルや画像の変更後は新しいパスになり、
既存のモデル・テクスチャキャッシュが古い内容を返すことを避けます。
旧出力は自動削除しません。再生中に読込済みの資産はエンジン側でもキャッシュされます。
配置だけの変更では資産は増えません。

## 最初の対応範囲

今回の機能は**静的なシーン配置モデルの配置と描画**です。
当たり判定・押し戻し・ライト・カメラ・Playerや敵の生成は、このJSONから自動設定しません。
Emptyにカスタムプロパティ `tkmax_tag` を付けると、SceneLayout::GetMarkers()からゲーム側へ位置を渡せます。
例としてplayer_startを保存できますが、現在のPlayer開始位置を勝手に変更することはありません。

- プロシージャルなBase Colorは画像へベイクしてから使ってください。
- PBR全体（メタリック、ラフネス、ノーマルマップ等）の再現は対象外です。
- スケルトンやアニメーションは現在の姿勢の静的メッシュとして出力します。
- コレクションインスタンスは実体化してから書き出してください。
- 非一様スケールの親に回転した子を置くなど、シアーが生じる場合はTransformを整理してから書き出してください。
- 特定のものだけ除外する場合はカスタムプロパティ `tkmax_exclude` をtrueにできます。

## エンジン側

SceneLayoutDataがJSONとモデル参照を検証し、SceneLayoutがObject3dの所有・更新・描画を担当します。
読込失敗時は前のシーン配置を保持します。JSONはgame.jsonやパーティクル設定とは別です。
モデルはSetModelによる自動読込・共有を利用し、カメラ切り替えにも追従します。
GameSceneには初期化・読込・更新・描画・終了と、ImGuiを呼ぶ処理だけを追加しています。

## 検証範囲

Pythonの座標変換とOBJ出力、回転・反転スケール・親子行列、シアー拒否を検証しています。
Blenderの座標から求めた結果と、実際のMyMathのTRSから求めた結果の一致も検証済みです。
生成OBJを実際のModel::LoadObjFileで読み、頂点・法線の規約も確認しています。
GPU部分を代替した検証では、シーン配置読込・失敗時の保持・可視性・再読込を確認しています。
Python/ImGuiの構文検査、Visual StudioプロジェクトのXML検査、git diff --checkも行っています。
Blender本体でのアドオン操作と、Windowsでの全体ビルド・実画面は未検証です。
