# Debugのゲームビュー

Debugビルド（`_DEBUG` と `USE_IMGUI` の両方が有効）では、ゲームの完成画面を
ImGuiの「ゲームビュー」へ表示します。Releaseは従来どおり画面全体へ描画し、ImGuiは表示しません。

## 操作

- 起動すると、右上にゲームビュー、左と下に編集ウィンドウがドッキングされます。
- 境界をドラッグすると領域の大きさを変更できます。
- ウィンドウのタブやタイトルバーをドラッグして、好きな場所へドッキングできます。
- レイアウトは既存の `project/imgui.ini` に保存されます。
- ゲームビューは16:9を維持して領域内へ収め、余白は黒く表示します。
- アプリはメインモニター全体を使うボーダーレスのフルスクリーンで起動します。
- Esc キーでアプリを終了できます。
- デバッグカメラのマウス操作とスプライトのクリック選択は、ゲームの画像上で有効です。
  縮小・移動したゲームビューに合わせてスプライト編集のマウス座標と枠表示も変換します。

ゲーム自体の描画解像度は1280×720のままです。ビューを小さくしても、
ゲームの座標系・カメラの縦横比・スプライトの保存座標は変わりません。

## 描画順

1. 従来のRenderTextureへ3Dと背景を描画します。
2. ポスト処理の最終出力を、Debug専用のゲームビュー用RenderTextureへ描画します。
3. ライン・前面スプライト・シーン切り替えフェードも同じ描画先へ重ねます。
4. ゲームビュー用テクスチャをRenderTargetからPixelShaderResourceへ遷移します。
5. バックバッファへ戻し、ゲーム画像を含むImGui全体を描画します。
6. 従来のPostDrawでPresentし、GPU完了を待って次フレームへ進みます。

バックバッファのサイズ変更はDebugのみです。ゲーム用テクスチャ・深度・Viewportの
サイズを変えず、前フレームのGPU完了後にバックバッファだけを再生成します。
ImGuiのSRVヒープはフォントとゲーム画像で2枠を使います。

## 検証

- 実際のImGuiによる初期ドッキング・画像登録・表示サイズ変更・マウス入力の振り分けを確認。
- 縦長/横長の領域での縦横比維持と、ゲーム座標と画面座標の往復変換を確認。
- 実際のSpriteGizmoで、半分の表示倍率での当たり判定とドラッグ、ビュー非表示時の操作解除を確認。
- GPU APIを代替し、複数フレームのRenderTarget/SRV遷移・描画先復帰・リサイズを確認。
- Debug/Releaseの構文・分岐、プロジェクトXML、差分形式を確認。

Windowsでの全体ビルド・D3D12実機描画は未検証です。
